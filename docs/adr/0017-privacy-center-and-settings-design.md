# Phase 7 design: privacy center and settings

Phase 7 lets the user control exactly what is captured and kept, and gives ClipBench a Settings window. This record holds the decisions behind it. Where PLAN.md said something else, it says so.

## Decisions

1. **The owner approved the plan and these choices (2026-11-05).**
   - The default exclusion list is the list in decision 4, and the user can add and remove entries.
   - Incognito is switched off at every start.
   - Pinning a secret cancels its expiry.
   - The shortcuts can be changed in Settings and take effect at once.
   - The ranges of the numbers are the ones in decision 2.
2. **Settings are a flat set of choices with ranges, and a number out of range is moved to the nearest end.** The file stays at version 1: every new key is optional, a file without it gets the default, and keys a version does not know are ignored, so an older file loads and a newer file does not break an older app. Ranges: history count 10 to 10,000 (1,000), age 1 to 365 days (30), size 16 to 2,048 MiB (256), secret expiry 15 to 3,600 seconds (120). Normalizing replaces a shortcut that would stop people typing, and a shortcut used for both actions, with the default. A damaged file still gives the defaults and is kept as `settings.json.bad`.
3. **Settings reach the running app through one applier.** `SettingsApplier` listens to the settings and, on every change and once at start, sets the history limits (and removes what no longer fits, from memory and disk), the secret expiry and the excluded programs of the capture filter. Failures are logged by error code and never stop the app. The rest (masking, shortcuts, start-up, screen capture) is applied where it is used.
4. **The exclusion list matches by executable name.** A name matches whatever its case, folder or `.exe`. It is kept as plain program names in `settings.json`; the names are not clip content, but they do say which password manager someone uses (see the threat model). A list of at most 200 names of at most 100 characters, with no control characters and none of `" < > | : * ?`. The default holds KeePass, KeePassXC, 1Password, Bitwarden, Dashlane, NordPass, Enpass, RoboForm, RoboTaskBarIcon, KeeperPasswordManager, Proton Pass and CredentialUIBroker (the Windows credential prompt). Keeper's (`keeperpasswordmanager`) and RoboForm's tray program (`RoboTaskBarIcon`) were checked against online listings; Proton Pass's could not be confirmed and the others are best knowledge. A wrong name only excludes nothing, so the list is to be checked against installed programs. Managers that mark their copies private are skipped anyway by the privacy markers, so this list is a second line of defence. A user who empties the list gets an empty list; only a missing or damaged value gives the default.
5. **A clip that looks like a secret expires.** The clip carries an optional `ExpiresAt`. The library sets it when a new, unpinned text clip is added and the detector finds a secret: the capture time plus the chosen seconds. Copying the same secret again starts the time again. Images and file lists never expire (a path is not a secret). Pinning a clip, or putting it on a board, cancels the expiry in memory and in the database, because that is a choice to keep it, and unpinning does not bring it back. The expiry is stored in the clip's row (a plain integer, like the capture time, never the content). A sweeper removes expired clips every second and once at start: from the in-memory history and the search, and from the database, where deletes are scrubbed (`secure_delete`, then the write-ahead log is emptied), as in Phase 2. A clip past its time is also never loaded or returned by the store before it is swept. The popup masks secrets as before; masking can be switched off, and then a secret is shown, previewed and transformed like any text.
6. **Incognito is not saved, and it is the old pause.** One switch, with one state in the capture service. The tray item and the Settings switch change it and follow each other. It is on only until the user turns it off or ClipBench exits, so a forgotten switch cannot silently stop recording after a restart. The tray icon shows a second picture, greyed out with a slashed badge, and the tool tip says "incognito". If the second picture cannot be loaded, the tool tip still says it. The tray text changed from "Pause capturing" to "Turn on incognito".
7. **Start with Windows is one value in the user's own Run key.** `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, value `ClipBench`, the quoted full path of the program and nothing else. No elevation, no other key, never another program's value. It is off by default. The choice is saved only after Windows accepted the entry, so the setting never claims what is not in place. At start, when the choice is on, an entry that is missing or points to an old folder (a portable copy that was moved) is written again; when it is off, nothing is touched, because an entry could belong to an installer. The entry has no "silent" argument: ClipBench lives in the tray and opens no window by itself.
8. **The first-run question lives in the Settings window, not in a dialog.** On the first run the Settings window opens on General with a card asking whether to start with Windows. Yes writes the entry; No changes nothing; either way the question is not asked again. If Windows refuses, the question stays and the reason shows. Closing the window without answering asks again at the next start. A modal dialog was not built: the window has to exist anyway, and a card is part of it.
9. **Wipe all reuses the Phase 2 repository wipe and keeps the database and key.** Every clip (pinned too), board and snippet is deleted, the file is rebuilt and the log emptied. The app keeps running, so the database file and its key stay and are empty and unused; removing the files and the key is what Start fresh does, and what deleting the folder does. This differs from the glossary's earlier text ("together with its encryption key"), which is corrected. A collect session and a paste queue hold copies in memory and are ended first, even when the disk wipe fails. A copy that is being saved finishes before the wipe starts (they share one lock), so it cannot survive it. When the store cannot be wiped, memory keeps what it had, so the window never hides what is still on disk, and the reason is shown. The Settings window asks first and says what will be deleted.
10. **Shortcuts are bound through a service that can change them.** `HotkeyBindings` claims the new shortcut before it gives the old one back, so a refused change leaves the old shortcut working, and refuses a shortcut that already does the other thing. A shortcut is saved only after Windows gave it. The command-line switches `--hotkey` and `--collect-hotkey` still override the saved ones at start-up, for tests. The window's boxes turn the keys pressed into the text a person would type (`Ctrl+Alt+K`) and the same parser judges it. No keyboard hook is involved.
11. **The Settings window replaces the Snippets window.** Sections: General, Shortcuts, History, Privacy, Paste, Snippets, About. The snippet editor is the same view model and the same controls, with the same keys (Ctrl+S, Ctrl+N, Ctrl+Delete, Esc) while that section is open. Ctrl+E in the popup and the tray's **Settings…** item open the window. The tray menu lost **Restore clipboard after paste** (it is a switch under Paste) and **Snippets…** (it is a section). Closing the window only hides it; unsaved snippet changes are dropped when the snippets are shown again. Escape backs out of one thing at a time: the wipe question, the delete question, unsaved changes, the window.
12. **The window follows the screen-capture choice at once.** The popup, the queue window and the Settings window are excluded from screenshots and screen sharing while the choice is on (the default) and are allowed in when it is turned off, with no restart. `--allow-screen-capture` still turns protection off for tests.
13. **About opens the project's page through the user's browser.** The address is a constant in the program; the click raises an event and the window asks Windows to open it. ClipBench itself opens no connection, and nothing is opened without a click. This is the only place the app hands an address to Windows (Phase 9's network test must expect it).
14. **Nothing here logs content.** New events: the history was wiped, the start-up entry failed. They carry error codes only. Program names, shortcuts and settings values are not logged.

## Considered options

- **Saving incognito.** Rejected: a forgotten switch would silently stop recording after a restart.
- **Deleting the key in the in-app wipe.** Rejected for now: the running app would have to reopen a new database, rebuilding every store and catalog. The data is gone and scrubbed either way, and the key protects nothing once the database is empty.
- **A modal first-run dialog.** Rejected, see decision 8.
- **Several start-up entries or a scheduled task.** Rejected: the Run key is the one place the user can see and remove in Windows' own Startup apps page, and it needs no elevation.
- **Settings in the registry.** Rejected: the JSON file already exists, is capped and tested, and is easy to inspect and back up.
